## Khatm Circle links (`/k/<slug>`)

GitHub Pages cannot route dynamic paths, so:

1. `https://tibyaan.ai/k/<slug>` does not exist as a file. GitHub Pages answers with `404.html`
   (HTTP status 404), whose first script redirects `/k/<slug>` to `/k/?c=<slug>`.
2. `k/index.html` (a real page, status 200) reads `?c=` (or the path), calls the circle's regional
   API, and then puts the pretty URL `/k/<slug>` back with `history.replaceState`.

`/k/?c=<slug>` also works directly. The slug's last part is the circle code, whose first letter is
the region (`E` → `api-eu.tibyaan.ai`, `A` → `api-us.tibyaan.ai`), so no lookup service is needed.
API contract: `mushaf-api/docs/KHATM_CIRCLE_CONTRACT.md`. The page only uses `textContent`, keeps the
claim token in `localStorage` (`tibyaan.khatm.<code>`), and offers "Open in Tibyaan"
(`tibyaan://k/<slug>?claim=<token>`, an `intent://` URL on Android).

Limits of static hosting: link-preview crawlers see the 404 status and the generic `404.html`
Open Graph tags, so a shared link cannot show the circle's own title. That would need an edge
function (e.g. a Cloudflare Worker) in front of `/k/*`.

Store buttons: set `APP_STORE_URL` and `PLAY_STORE_URL` at the top of the script in
`k/index.html` once the apps are live (empty = "coming soon", linking to the home page).

- **TODO (owner): Android fingerprint.** `sha256_cert_fingerprints` is empty. Add the Play Console
  *App signing key certificate* SHA-256 (Setup → App signing), not the upload key; add the
  upload/debug fingerprints too if sideloaded builds should open links.

Hosting notes:

- `.nojekyll` is required: without it GitHub Pages runs Jekyll, which skips dot-directories, and
  `/.well-known/` would 404.
- `assetlinks.json` is served as `application/json`. `apple-app-site-association` has no extension,
  so GitHub Pages serves it as `application/octet-stream`. Apple's CDN has accepted that for other
  GitHub Pages sites, but verify after deploying: `curl -sI https://tibyaan.ai/.well-known/apple-app-site-association`
  (200, no redirect) and `https://app-site-association.cdn-apple.com/a/v1/tibyaan.ai`. If Apple rejects it,
  put Cloudflare in front and set `Content-Type: application/json` for that path.
- Both files must be reachable at the apex `tibyaan.ai` without redirects (the app's associated domain
  is `applinks:tibyaan.ai`).
- A Universal Link opened from a page on the same domain stays in Safari, which is why the pick
  page's button uses the `tibyaan://` scheme.
